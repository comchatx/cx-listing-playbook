# Reviews and Q&A text

Read 2026-10-14 by the research seat. Tags: [official] Amazon's own page or document; [opinion] a named practitioner; [research] published research; [seat] the seat's own reasoning, never a skill position.

## What this covers

**Funnel stages.** Star rating and rating count are shown beside the title in search results, so they act at **click-through**. Review content acts at **conversion**: the reviews section, the AI "Customers say" paragraph, and the shopping assistant's answers on the detail page. Amazon tests what it shows: in 2024 it confirmed a limited test that hid stars and counts from search results (Fortune, 2024-08-15, below). So which stage a rating acts on is a fact about the page on a given day, not a constant. Review and return *topics* are also the main **diagnostic** for one trigger family: "returns up, negative-review themes clustering, listing promise not matching the product."

**Skills fed.**
- `listing-review`: what reviews and returns say about which stage dropped; which element (title, bullets, images, A+) made a promise the product does not keep; what competitors are praised and faulted for.
- `listing-change-log`: what the before/after text claims, so later review themes can be checked against it.
- `effect-review`: rating and count moving inside an observation window are confounders. Amazon's 2026 variation review-sharing change can move a child ASIN's rating and count with no listing edit. Return data arrives late.
- Report script: the FBA returns report and the seller-fulfilled returns reports carry return reasons. The FBA one also carries customer comments.

**Why a senior operator cares.** (Gap fill 2026-10-14: since February 2026 a drop in a child's displayed rating or count may be Amazon's theme-based review split rather than new negative reviews, and Keepa's variation-specific rating count has been frozen since 2025-04-09, so competitor review velocity read from Keepa may be stale; see items 32–35 and 44 and the Keepa entry under practitioners.) Ratings and review text are the one funnel input the seller cannot write, and the one most hedged by policy. Over 2024–2026 Amazon changed several things here: review-sharing across variations (2026), seller contact for critical reviews (removed per Amazon staff in forum replies, about June 2026), Q&A's place on the page, and Rufus becoming "Alexa for Shopping" (2026). Two machine sources that this team's earlier notes listed as missing do exist: the Customer Feedback API and Data Kiosk's per-ASIN review, return and return-defect metrics. They are the largest correction this file makes to the roadmap's angle table, which says "no API" for review and Q&A text.

## Amazon's own rules and guidance

### A. What the SP-API gives (machine-readable; GUIDANCE about data, RULES about access)

1. **The Customer Feedback API exists, version 2024-06-01, for sellers and vendors.** It provides "insights from customer reviews and returns". Amazon says: "This API provides the same information as the Product Opportunity Explorer (OX) on Seller Central and Vendor Central." Release notes date it June 25, 2025. [official] (Customer Feedback API, https://developer-docs.amazon/sp-api/docs/customer-feedback-api, read 2026-10-14; SP-API release notes, https://developer-docs.amazon/sp-api/docs/sp-api-release-notes, read 2026-10-14)
2. **Seven operations, not six.**
   - `getItemReviewTopics`, `getItemReviewTrends` and `getItemBrowseNode` work by ASIN.
   - `getBrowseNodeReviewTopics`, `getBrowseNodeReviewTrends`, `getBrowseNodeReturnTopics` and `getBrowseNodeReturnTrends` work by browse node.
   - The paths are `/customerFeedback/2024-06-01/items/{asin}/reviews/topics`, `/items/{asin}/reviews/trends`, `/items/{asin}/browseNode`, `/browseNodes/{browseNodeId}/reviews/topics|trends` and `/browseNodes/{browseNodeId}/returns/topics|trends`.

   [official] (customerFeedback_2024-06-01.json, https://github.com/amzn/selling-partner-api-models/blob/main/models/customer-feedback-api-model/customerFeedback_2024-06-01.json, read 2026-10-14)
3. **What a topic reply holds.**
   - `getItemReviewTopics` returns the item's "ten most positive and ten most negative review topics". The `asin` "must be a child ASIN", and `sortBy` (`MENTIONS` or `STAR_RATING_IMPACT`) is required.
   - Each topic carries `asinMetrics` (`numberOfMentions`, `occurrencePercentage`, and `starRatingImpact`, which "can be positive or negative"), `parentAsinMetrics`, `browseNodeMetrics` and `childAsinMetrics` (the sibling child ASINs with the most and the fewest mentions).
   - It also carries `reviewSnippets` ("A list of up to three snippets from reviews that contain the topic", an array of strings, `maxItems` 3) and up to five `subtopics`, each with its own snippets.
   - Any of these may be `null` "if there isn't enough topic data".
   - The reply carries a `dateRange`. The model's own example spans six months.

   [official] (customerFeedback_2024-06-01.json, as above)
4. **Trends are monthly over six months.** `getItemReviewTrends` returns an item's "positive and negative review trends for the past six months", with per-month `occurrencePercentage` for the ASIN, its parent and its browse node. [official] (customerFeedback_2024-06-01.json; Get Feedback Insights for an ASIN, https://developer-docs.amazon/sp-api/docs/get-feedback-insights-asin, read 2026-10-14)
5. **Return topics exist only by browse node.** "Return insights are only available at the browse node level." `getBrowseNodeReturnTopics` returns "the topics that customers mention when they return items in a browse node", and the trends operation gives monthly occurrence. There is no ASIN-level return-topic operation in this API. One discrepancy: the browse-node tutorial says to call `getBrowseNodeReturnTopics` twice with `sortBy`, but the model declares no `sortBy` on that operation. [official] (Customer Feedback API; Get Feedback Insights for a Browse Node, https://developer-docs.amazon/sp-api/docs/get-feedback-insights-browse-node, read 2026-10-14; customerFeedback_2024-06-01.json)
6. **Cadence, language and stores.** "The data provided by the Customer Feedback API is refreshed weekly." "This API is only available in English." Stores: US, UK, France, Italy, Germany, Spain, Japan. [official] (Customer Feedback API)
7. **Access (RULE).** Every operation needs at least one of the roles "Brand Analytics" or "Selling Partner Insights". The tutorials say Selling Partner Insights "if you are supporting a seller" and Brand Analytics for a vendor. **No page read says whether a seller may query ASINs other than their own** (for example a competitor's child ASIN). [official] (Customer Feedback API; Get Feedback Insights for an ASIN)
8. **Rate (figure for humans; it lives on Amazon's rate-limit page).** 1 request per second with a burst of 10 for each of the seven operations, per account-application pair, as read 2026-10-14. The model JSON states no figure; it declares an `x-amzn-RateLimit-Limit` response header ("Your rate limit (requests per second) for this operation"), so the binding value is read from that header or the rate-limit page at run time. [official] (Customer Feedback API Rate Limits, https://developer-docs.amazon/sp-api/docs/customer-feedback-api-rate-limits, read 2026-10-14; customerFeedback_2024-06-01.json, re-read 2026-10-14)
9. **Data Kiosk seller analytics carries per-ASIN review state, review activity, returns and return-defect topics.** The dataset is `analytics_sellerAnalytics_2025_03_31`, added in the September 30, 2026 release notes. Its `Reviews` group holds:
   - `lowRatingReviewCount` and `totalReviewCount` ("received for the product in the selected time period");
   - `criticalReviewRate` (low-rating divided by total);
   - `displayRating` ("Rounded star rating shown on the product detail page");
   - `rawRating` ("Unrounded average star rating");
   - `totalRatingCount` ("Total number of verified buyer reviews contributing to the product's star rating, as of the requested date. Differs from totalReviewCount, which counts reviews received in the selected time period").

   `displayRating`, `rawRating` and `totalRatingCount` "Reflect[s] the overall rating state as of the requested date, not activity within the period". The `Defects` group holds `returnDefectTopic`, `returnDefectFrequency` ("trailing six months"), `returnDefectContribution` and `returnDefectRecommendations` ("Recommended actions to address the return defects associated with this topic"). The `Returns` group holds `returnedUnits`, `totalRefundAmount` and `returnedRate`. **This is ASIN-level return-topic data, which the Customer Feedback API does not give.** [official] (analytics_sellerAnalytics_2025_03_31.graphql, https://github.com/amzn/selling-partner-api-models/blob/main/schemas/data-kiosk/analytics_sellerAnalytics_2025_03_31.graphql, read 2026-10-14; SP-API release notes)
10. **Data Kiosk timing (figures for humans; they live in the guide and schema).**
    - The guide says metrics are "ready after 34 hours".
    - Return data lags "about 45 days", and returns are attributed to the ship day, so `returnedRate` "may appear artificially low for recent dates".
    - Defect metrics are "snapshots computed over a trailing six-month window, not period sums", so they cannot be added across periods, and "The topic can change between snapshots as the window moves."
    - The guide lists only three review metrics. The schema has six.
    - Reviews, returns and defects come with "Sales and traffic access" (the schema gates the `reviews`, `defects` and `returns` groups on the right `analytics_sales_and_traffic_view_pa`), and a field the app is not authorized for "returns an authorization error rather than a null value".
    - Access is described at three levels on three Amazon pages, and none of them maps one onto another. The guide: "Access to the seller analytics dataset is governed by the role assigned to your application", with two access levels ("Sales and traffic access", "Sales and lending access") and no role name. The schema: a PAAM right per field (`analytics_sales_and_traffic_view_pa`). The Data Kiosk API page: every operation (`createQuery`, `getQuery`, `getQueries`, `getDocument`, `cancelQuery`) lists "Required roles (need at least one) Brand Analytics", and "Each field available with Data Kiosk requires a certain role." So the operation role is Brand Analytics, and which role grants the per-field right is not stated on any page read; it is settled by the first query (Open question 3). Other files that name Selling Partner Insights for a different Data Kiosk dataset (the Economics dataset in `angles/paid-keywords.md`) are about that dataset, not this one.
    - The schema's own wording of the lag, on `returnedUnits`: "Return data is computed with a delay of about 45 days, so the most recent ~45 days may be empty or incomplete." `returnedUnits` counts units returned "with a resolution (refund or replacement), including returnless refunds, mapped to the day each unit was shipped."

    [official] (Seller Analytics Dataset Use Case Guide, https://developer-docs.amazon/sp-api/docs/seller-analytics-dataset-guide, read 2026-10-14; analytics_sellerAnalytics_2025_03_31.graphql; Data Kiosk API, https://developer-docs.amazon/sp-api/docs/data-kiosk-api, read 2026-10-14)
11. **The vendor dataset has review and return topics as strings**: the schema types `CustomerReviewTopics` (fields such as `negativeReviewTopics`, `negativeReviewTopicImpactOnStarRating`, `negativeReviewTopicTrends`, each a `String`) and `CustomerReturnTopics` (`browseNodeReturnTopics`, `browseNodeReturnTopicTrends`, browse-node level). The release note of October 1, 2025 words it "Added the customerReviews and customerReturnTopics metrics to the Vendor Analytics Data Kiosk dataset." It is vendor-only. Noted so a skill does not send a seller there. [official] (analytics_vendorAnalytics_2024_09_30.graphql, read 2026-10-14; SP-API release notes)
12. **Returns reports.**
    - The FBA returns report "Contains customer returned items received at an Amazon fulfillment center, including Return Reason and Disposition". Its fields include `reason` and customer comments. It is updated daily and can only be requested, not scheduled.
    - The seller-fulfilled returns reports carry a return reason code but no comments field. "You can request up to 60 days of data in a single report." The page's note on excluded data names "FBA returns" (use the FBA returns report instead) and "Returnless refunds".
    - Report type names and options belong to door.md; the operation is `createReport`.

    [official] (FBA reports, https://developer-docs.amazon/sp-api/docs/report-type-values-fba, read 2026-10-14; Returns reports, https://developer-docs.amazon/sp-api/docs/report-type-values-returns, read 2026-10-14)
13. **Seller feedback is a different thing from product reviews.** The seller feedback report "Contains negative and neutral feedback (one to three stars) from buyers who rated the seller's performance". It is about the seller, not the product. [official] (Performance Reports, https://developer-docs.amazon/sp-api/docs/report-type-values-performance, read 2026-10-14)
14. **No SP-API operation reads full review text or customer questions.** A scan of the model files in `amzn/selling-partner-api-models` (main, 2026-10-14; the verifier re-scanned all 70 JSON models under `models/` for operation ids, paths and descriptions mentioning review, question or answer) found three things that touch reviews: the seven Customer Feedback operations, the two Solicitations operations, and Data Kiosk's review counts and ratings (a GraphQL schema, not a model JSON). No operation reads or answers Customer Questions & Answers. The analytics report types carry no review or rating fields; the Sales and Traffic report's `feedbackReceived` and `receivedNegativeFeedbackRate` are seller feedback, not product reviews. [official] (selling-partner-api-models tree, read 2026-10-14; Analytics reports, https://developer-docs.amazon/sp-api/docs/report-type-values-analytics, read 2026-10-14)

### B. Asking for reviews (RULES)

15. **The Solicitations API is the programmatic "Request a Review".**
    - `createProductReviewAndSellerFeedbackSolicitation` "Sends a solicitation to a buyer asking for seller feedback and a product review for the specified order. Send only one productReviewAndSellerFeedback or free form proactive message per order."
    - `getSolicitationActionsForOrder` lists what is available for an order.
    - "Buyers cannot respond to solicitations sent by this API", and these solicitations do not appear in Messaging.
    - Rate 1/s, burst 5.
    - Roles: Buyer Solicitation or Product Listing.

    [official] (solicitations.json, https://github.com/amzn/selling-partner-api-models/blob/main/models/solicitations-api-model/solicitations.json, read 2026-10-14; Solicitations API, https://developer-docs.amazon/sp-api/docs/solicitations-api, read 2026-10-14)
16. **The window (RULE; figure on Amazon's page).** "You can request solicitation within a time frame of five days after the `EarliestDeliveryDate`" through 30 days after `LatestDeliveryDate`. "Calling the Solicitations API outside this time frame will lead to unexpected API errors." Check `OrderStatus` is `Shipped` and do not send a duplicate. [official] (Set up the Solicitations API, https://developer-docs.amazon/sp-api/docs/set-up-the-solicitations-api, read 2026-10-14)
17. **Amazon's Seller Central button text** (quoted by Jungle Scout, so second-hand):

18. **Customer-side Community Guidelines (RULE).**
    - Not allowed: to "Create, edit, or remove a review in exchange for compensation".
    - "Reviews influenced by compensation through any channel, including social media sites, violate our guidelines".
    - "Accepting free products or compensation directly from sellers or brands in exchange for reviews is strictly prohibited". Vine is the exception.
    - No reviews of "products that you have financial interest in".
    - A review is fine when "a seller encourages you to leave an unbiased, un-incentivized review". Offers to "change, remove a negative review or leave a positive review" in exchange for a refund should be reported.
    - "If we reject or remove your review for guidelines violation, you won't be allowed to review that product again."

### C. How ratings and reviews are formed and shown (GUIDANCE about Amazon's systems)

23. **The star rating is not a simple average.** It is calculated "using machine-learned models instead of a simple average", which weight factors such as "how recent the rating or review is". [official] (Get 4-star ratings for your products using Customer Review Insights, Avi Ravi, Amazon, 2022-09-15, https://sell.amazon.com/blog/customer-review-insights, read 2026-10-14) The customer help page "How are Product Star Ratings Calculated?" was unreachable (503).
24. **Review sharing across variations changed in 2026 (RULE).** The News_Amazon announcement says:
    - "Starting February 12, 2026" (rolled out by category through May 31, 2026), "Reviews will only be shared between variations with minor differences that don't affect functionality".
    - "Reviews will no longer appear on variations with significant differences", which may change star ratings and review counts.
    - Variations that still share: color or pattern, same-function size, pack size or quantity, secondary scent, and model fitment.
    - Sellers get "email notification 30 days before any changes affect your products".

    [official] (Changes to review sharing across product variations starting Feb 12, https://sellercentral.amazon.com/seller-forums/discussions/t/a572986d-9bb1-4e91-a53f-41c575874dd7, read 2026-10-14)
25. **AI review highlights ("Customers say").**
    - What it is: an AI-generated paragraph of "shared positive, neutral, and negative opinions from customers", built from "text-based reviews from Amazon Verified Purchases" when "multiple customers share the same opinion".
    - Feature tags: a green check means mostly positive, an orange minus mostly negative, gray neither.
    - Absence can mean too few shared mentions; the page also limits highlights to some stores (it names the U.S., UK, Australia, India, Singapore and the United Arab Emirates). No publication date is shown on the page.

    [official] (Here's how Amazon's AI-generated review highlights help you make better shopping decisions, Ivy Levine, https://www.aboutamazon.com/news/amazon-ai/amazon-ai-generated-review-highlights, read 2026-10-14)
26. **Seller-side Customer Review Insights** sits in Product Opportunity Explorer under Growth. It shows topics, snippets and "the topic's impact on star rating". A forum announcement added Review Trends ("for brands"), Parent ASIN insights, ASIN Benchmarking against the category rating, and Topic Drilldown. It is the same information as the Customer Feedback API (item 1). [official] (Get 4-star ratings… Customer Review Insights; Use reviews to improve product launches with new Customer Review Insights, Josh_Amazon, https://sellercentral.amazon.com/seller-forums/discussions/t/97b62354-466b-411b-907c-d7e9542f78cf; read 2026-10-14)
27. **Voice of the Customer / NCX** (Amazon help text pasted into a forum thread by a seller and excerpted, with a link to the help page, by CR_Amazon, both shown "2 years ago"; the help page itself was not reached):
    - "The NCX rate is the number of orders for which a customer reported a product or listing issue divided by total orders."
    - The sources are "returns, refunds, customer service contacts, buyer-seller messaging, seller feedback, A-Z claims, and product reviews".
    - The NCX Review Rate counts 1–2 star reviews that cite product or listing issues, divided by total orders; per the pasted text it includes only reviews received after January 2024.
    - CX Health compares an offer's NCX rate "with those of similar offers".
    - "it may take several weeks for actions you take to be reflected".

    No SP-API operation returning NCX was found. [official, via forum repost] (NCX rate, https://sellercentral.amazon.com/seller-forums/discussions/t/22ede306-660c-4f1c-bfe4-52dd71ed73cb, read 2026-10-14)
28. **Fake-review detection includes ad investment as a signal.** "Machine learning models analyze a multitude of proprietary data including whether the seller has invested in ads". Amazon adds (an Amazon spokesperson quoted on the page, paraphrased here) that a product may gain reviews quickly because the seller advertised heavily or priced well. No publication date is shown on the page. Amazon "proactively blocked more than 200 million suspected fake reviews" in 2022. [official] (How Amazon is using AI to ensure authentic customer reviews, https://aboutamazon.com/news/policy-news-views/how-ai-spots-fake-reviews-amazon, read 2026-10-14)

32. **Review sharing is decided by the variation theme (RULE).** The News_Amazon follow-up post opens "On January 7, 2026, we announced that reviews will only be shared between product variations with minor differences". 35. **Amazon's review-sharing guideline page, now read.** The page is "Guidelines for reviews shared across product variations" (G74DLBUEHT5GY88C, version 3, revision 4).

## Published research

- **Chevalier, J. A. & Mayzlin, D.**, "The Effect of Word of Mouth on Sales: Online Book Reviews". NBER Working Paper 10148 (2003); *Journal of Marketing Research* 43(3), 2006 (journal citation from search metadata; the NBER page was opened). Finding, narrowly: on Amazon.com and BarnesandNoble.com books, better reviews at one site raise that site's *relative* sales, and one-star reviews move sales more than five-star reviews. **Transfer:** it is Amazon data and the asymmetry is the useful part (a few new 1-star reviews deserve more weight than the same number of 5-star ones). It is books in 2003, and relative rather than absolute sales. [research] (NBER w10148, https://www.nber.org/papers/w10148)
- **Spiegel Research Center (Northwestern) with PowerReviews**, "How Online Reviews Influence Sales" (June 2017 report). The data are *not Amazon*: two lower-priced CPG retailers (22 categories, 111,460 SKUs) and one high-end gift retailer (about 15.5M page views, 1,800 products). The findings:
  - "The purchase likelihood for a product with five reviews is 270% greater than the purchase likelihood of a product with no reviews." This is the gift retailer only.
  - At the same gift retailer, displaying reviews raised conversion 190% for a lower-priced product and 380% for a higher-priced one (the "lower-priced" here is within a high-end gift store, not the CPG retailers).
  - "Across product categories, we found that purchase likelihood typically peaks at ratings in the 4.0 - 4.7 range".
  - "nearly all of the increase in purchase likelihood occurs within the first 10 reviews, and the first five reviews drive the bulk of this increase" (gift retailer data).
  - Verified buyers' average was 4.34 against 3.89 for anonymous reviewers.

  The underlying papers it cites are Askalidis & Malthouse (RecSys 2016), Maslowska, Malthouse & Bernritter (*International Journal of Advertising* 36(1), 2017), Malthouse, Maslowska & Viswanathan (*Decision Support Systems*, 2017) and Askalidis, Kim & Malthouse (*Decision Support Systems* 97, 2017). **Transfer:** weak on figures and moderate on shape. The first reviews matter most and higher-priced, higher-risk products depend more on reviews; both plausibly hold on Amazon. The 270% does not transfer. [research] (report PDF via https://www.xait.com/hubfs/Spiegel_Online-Review_eBook_Jun2017_FINAL.pdf; Spiegel page https://spiegel.medill.northwestern.edu/how-online-reviews-influence-sales/)
- **Ghose, A. & Ipeirotis, P. G.**, "Estimating the Helpfulness and Economic Impact of Product Reviews: Mining Text and Reviewer Characteristics", *IEEE Transactions on Knowledge and Data Engineering* 23(10), 2011. Amazon.com data over 15 months. "the extent of subjectivity, informativeness, readability, and linguistic correctness in reviews matters in influencing sales". Reviews that mix objective and highly subjective sentences are negatively associated with sales. **Transfer:** review text, not just stars, carries sales signal on Amazon, which supports reading topics as well as counts. [research] (https://pages.stern.nyu.edu/~aghose/helpfulness_print.pdf)
- **He, S., Hollenbeck, B. & Proserpio, D.**, "The Market for Fake Reviews", *Marketing Science* (2022; citation per INFORMS release). Amazon products buying fake reviews on Facebook saw "a significant increase in average rating and sales rank", but the sales-rank effect "disappears after roughly one month" (MPRA abstract). After the purchases stop "average ratings fall significantly" and the share of one-star reviews rises. The deletion figure is from the INFORMS release, quoting Proserpio, not the abstract: "roughly half of their reviews were eventually deleted, but the deletions occurred with an average lag of over 100 days." **Transfer:** a direct Amazon finding. A competitor's sudden review burst may be manipulation and may later be deleted, so a competitor's count can drop with no change on either side. That is a control-set confounder for effect-review. [research] (MPRA 105507, https://mpra.ub.uni-muenchen.de/105507; INFORMS release, 2022-09-09)
- **Luca, M.** (HBS working paper, 2011; reported by HBS Working Knowledge, 2011-10-24). On Yelp, "each ratings star added on a Yelp review translated to anywhere from a 5 percent to 9 percent effect on revenues" (Washington State restaurant revenue data); the article reports chains largely unaffected and the effect concentrated in independent restaurants. The method is regression discontinuity at half-star rounding thresholds. **Transfer:** only the mechanism. The *displayed, rounded* rating is what moves behaviour, which is why Data Kiosk's `displayRating` is distinct from `rawRating`. Neither the size nor the setting transfers. [research] (https://www.library.hbs.edu/working-knowledge/the-yelp-factor-are-consumer-reviews-good-for-business)

Early buyers' preferences differ from later buyers', so the structure of ratings over time is biased. **Transfer:** a rating may drift over a product's life with no listing change, so a rating trend in an observation window is not by itself an effect of the edit. [research] (RePEc, https://ideas.repec.org/a/inm/orisre/v19y2008i4p456-474.html)

[research] (https://www.amazon.science/publications/why-do-customers-return-products-using-customer-reviews-to-predict-product-return-behaviors)

- **Archak, N., Ghose, A. & Ipeirotis, P. G.**, "Deriving the Pricing Power of Product Features by Mining Consumer Reviews", *Management Science* 57(8), 1485–1509, 2011. Data: "a unique data set from Amazon containing sales data and consumer review data for two different groups of products (digital cameras and camcorders) over a 15-month period". The authors decompose "textual reviews into segments describing different product features". They argue that "the textual content of product reviews is an important determinant of consumers' choices, over and above the valence and volume of reviews". **Transfer:** this is the closest published analogue to reading Customer Feedback *topics*. It shows that feature-level opinions in Amazon review text carry sales signal beyond stars and counts. The limits: two electronics categories, the late 2000s, and sales, not detail-page conversion. [research] (Crossref record, DOI 10.1287/mnsc.1110.1370, abstract read through https://api.crossref.org, 2026-10-14)
- **Ludwig, S., de Ruyter, K., Friedman, M., Brüggen, E. C., Wetzels, M. & Pfann, G.**, "More than Words: The Influence of Affective Content and Linguistic Style Matches in Online Reviews on Conversion Rates", *Journal of Marketing* 77(1), 87–103, 2013. The authors "employ text mining to extract changes in affective content and linguistic style properties of customer book reviews on Amazon.com" and use "A dynamic panel data model". The findings:
  - "the influence of positive affective content on conversion rates is asymmetrical, such that greater increases in positive affective content in customer reviews have a smaller effect on subsequent increases in conversion rate. No such tapering-off effect occurs for changes in negative affective content".
  - "positive changes in affective cues and increasing congruence with the product interest group's typical linguistic style directly and conjointly increase conversion rates".

  **Transfer:** Amazon data with conversion as the outcome. Its point is that new negative content keeps moving conversion where added positive content tapers off, which supports weighting new negative topics. It measures emotion and style, not product topics. It covers books. How the authors obtained Amazon conversion rates is not in the abstract; the full text was not reachable (publisher 403). [research] (Crossref record, DOI 10.1509/jm.11.0560; Maastricht University research portal, https://cris.maastrichtuniversity.nl/en/publications/17910500-8317-4e7c-9521-c1dfbe23b5c8; both read 2026-10-14)
- **Liu, X., Lee, D. & Srinivasan, K.**, "Large-Scale Cross-Category Analysis of Consumer Review Content on Sales Conversion Leveraging Deep Learning", *Journal of Marketing Research* 56(6), 918–943, 2019.
  - Abstract: the data are "an e-commerce site" with "500,000 reviews of 600 product categories". Supervised deep learning tags "six theory-driven content dimensions", and the design is "a regression discontinuity in time". "aesthetics and price content significantly increase conversion across almost all product categories". Review content matters more "when the average rating is higher, ratings variance is lower, the market is more competitive or immature, or brand information is not accessible". Consumers "rely on it for products that are expensive or of uncertain quality". Reordering reviews by content can equal "a 1.6% price cut".
  - **Correction to the gap brief: this is not Amazon data.** The NET Institute working paper by the same authors (#16-09, September 2016) says: "The data come from a major online retailer in the United Kingdom". It covers 243,000 consumers over February–March 2015, in "Technology as well as Home and Garden", with 583 sub-categories. A footnote says the data "also include textual content like questions and answers", which the paper counts as reviews. The six dimensions are Aesthetics, Conformance, Durability, Feature, Perceived Quality and Price. In the working paper's Table 6 (cross-sectional "Variety" model), Aesthetics and Price are significant in the PC sample only; none of the six is significant in the mobile sample, and **Durability, Feature, Conformance and Perceived Quality are significant in neither**. The paper warns that the site showed reviews "in groups of five".
  - **Transfer:** the strongest causal design of the set, but on a UK retailer, not Amazon. It supports reading review *content* as a conversion input, especially for expensive or uncertain products. It does not show that durability or fit mentions move conversion. (Whether the JMR version uses the same retailer is not stated in its abstract; the 583 sub-categories match its "600 product categories".) [research] (Crossref records, DOIs 10.1177/0022243719866690 and 10.2139/ssrn.2848528; NET Institute Working Paper #16-09, http://www.netinst.org/Liu_16-09.pdf; read 2026-10-14; SSRN page 403)
- **Feng, M., Feng, Y. & Li, Y.**, "Online reviews, customer Q&As, and product sales: A PVAR approach", *PLoS One* 18(11): e0290674, 2023. The data are daily laptop sales on Amazon.com, "from August 2019 to November 2019" (the abstract says 120 laptops; the body reports 105 after exclusions). The findings include "review volume and answer valence positively affecting sales", and "answer volume was found to stimulate online reviews and enhance their valence." **Transfer:** Amazon Q&A as a sales input in the pre-Rufus page layout, for one high-involvement category. [research] (Crossref record, read 2026-10-14)
- **What the set does and does not support.** On Amazon data, review *text* carries purchase signal beyond stars and counts: Ghose & Ipeirotis, Archak et al. and Ludwig et al. The best causal design (Liu, Lee & Srinivasan) finds aesthetics and price content move conversion, on a UK retailer. **No study read measures the effect of Amazon's own Customer Feedback topics, or of durability or fit mentions, on Amazon conversion.** Reading topics as conversion drivers rests on this indirect evidence, not on a direct measurement.

## Positions

- **P-reviews-and-qa-1**: cx never says it has read a product's reviews. It says it read Amazon's review *topics and snippets* (Customer Feedback API) or rating counts, because no SP-API operation returns full review text. (customerFeedback_2024-06-01.json; selling-partner-api-models tree)
- **P-reviews-and-qa-2**: For the seller's own ASIN, cx takes the displayed rating, raw rating and rating count from Data Kiosk seller analytics. It keeps "rating state as of a date" (`displayRating`, `rawRating`, `totalRatingCount`) apart from "reviews received in a period" (`totalReviewCount`, `lowRatingReviewCount`, `criticalReviewRate`). (analytics_sellerAnalytics_2025_03_31.graphql; Seller Analytics Dataset Use Case Guide)
- **P-reviews-and-qa-3**: To read what customers praise and fault, cx calls `getItemReviewTopics` on the child ASIN twice, once with `MENTIONS` and once with `STAR_RATING_IMPACT`. It reads each topic's ASIN metrics against the parent and browse-node metrics, so "common in the category" is not read as "specific to this product". (Get Feedback Insights for an ASIN; customerFeedback_2024-06-01.json)
- **P-reviews-and-qa-4**: cx treats Customer Feedback data as a periodically refreshed view over several months, with the refresh cadence read from the Customer Feedback API page and the span from the reply's `dateRange`. It does not use it as a daily signal or as proof that an edit made last week changed what customers say. (Customer Feedback API; customerFeedback_2024-06-01.json)
- **P-reviews-and-qa-5**: For returns, cx uses the product's own return-defect topics from Data Kiosk and the FBA returns report's reason and customer comments, and the browse node's return topics from Customer Feedback as the category baseline. It never presents a browse-node return topic as this ASIN's. (analytics_sellerAnalytics_2025_03_31.graphql; Customer Feedback API; FBA reports)
- **P-reviews-and-qa-6**: cx does not judge a listing change by returns inside a window shorter than the return-data lag Amazon states in the seller analytics guide. It reads that lag at run time and says the return verdict waits. (Seller Analytics Dataset Use Case Guide)
- **P-reviews-and-qa-7**: When a negative review topic or return reason names a property the listing asserts (size, fit, compatibility, material, what is included), cx flags a possible listing-promise mismatch for the seller to check against the product, not as a proven cause. Amazon counts "product or listing issue" in NCX, and Amazon's own science finds review text predicts return reasons. (NCX rate; Why do customers return products?)
- **P-reviews-and-qa-8**: In an effect-review, cx records the rating, rating count and reviews received for the changed ASIN and for the competitor set across both baseline and observation windows. It treats a material movement as a confounder of click-through and conversion, never as the edit's effect. (analytics_sellerAnalytics_2025_03_31.graphql; Chevalier & Mayzlin; Li & Hitt)
- **P-reviews-and-qa-9**: cx checks whether a variation-family change in Amazon's review sharing landed inside the window: Amazon's notice email, or a step change in the child's rating count with no edit. When one did, the verdict on that window is "cannot tell". (Changes to review sharing across product variations starting Feb 12)
- **P-reviews-and-qa-10**: A sudden jump or later drop in a competitor's review count is noted as possibly manipulation or deletion. It is not read as the competitor's demand. (The Market for Fake Reviews; How Amazon is using AI to ensure authentic customer reviews)
- **P-reviews-and-qa-11**: cx never drafts, proposes or sends anything that offers value for a review, asks for a positive review, asks for a review to be changed or removed, routes unhappy buyers away from reviews, or uses variation grouping to pool reviews. (Community Guidelines; Customer Reviews tool | Sell on Amazon; Customer Product Reviews Policies repost)
