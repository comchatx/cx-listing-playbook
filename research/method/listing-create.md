# Creating a listing: the seller's stores, the product type, the schema, identity, the preview, the write and the read-back

Read 2026-10-27 by the research seat for brief 2026-10-26-87. Tags: [official] Amazon's own page, model or staff post; [opinion] a named practitioner or a seller's report; [research] published research; [seat] the seat's own reasoning, never a skill position.

## What this covers

This file covers the path from a seller's new product data and the marketplaces they name to a listing that Amazon shows as buyable and discoverable. It has these parts:

- **Where the seller sells.** The stores from `getMarketplaceParticipations`, with each store's language and currency.
- **New item or existing item.** How Amazon tells a product it already has (an offer-only listing on that ASIN) from one it does not (a new item with product facts).
- **The product type and its schema.** `searchDefinitionsProductTypes` and `getDefinitionsProductType`, read for each store, and which schema keywords decide what a value must look like.
- **Product identity.** GTIN, UPC and EAN; the brand; Brand Registry; the GTIN exemption.
- **The request.** `putListingsItem` with `productType`, `requirements` and `attributes`, in each store's language and currency, with images, fulfilment, price and the compliance attributes the store's schema names.
- **Variations.** Parent first, then children, with relationship and theme.
- **The preview, the write and the read-back.** `mode=VALIDATION_PREVIEW`, the submission's `submissionId` and `status`, asynchronous issues, and `getListingsItem` until `BUYABLE` and `DISCOVERABLE`.
- **Build International Listings,** which is Seller Central's tool, not the API's.
- **The sandbox:** what a static sandbox answer proves and what it does not.

The file extends `research/method/listing-writes.md`, which covers the write side of an existing listing (the schema, patch and put, the preview, `ACCEPTED`, the Catalog view, deletes, feeds and stores). Where that file already holds a rule, this file names its P-id rather than restating it. It also leans on `research/angles/marketplaces-and-languages.md` (stores, language tags, GPSR), `research/elements/attributes-and-browse-nodes.md` (product type, compliance attributes, restrictions), `research/elements/variations.md` (families), `research/elements/images-and-video.md` (image rules), `research/method/sp-api-access.md` (participations, the seller id, roles) and `research/angles/brand-protection-and-catalog-contribution.md` (brand roles).

## Amazon's own rules and guidance

### A. Where the seller sells

1. **RULE: the seller's stores.** `getMarketplaceParticipations` "Returns a list of marketplaces where the seller can list items and information about the seller's participation in those marketplaces." Each row carries `marketplace` (with `id`, `countryCode`, `defaultCurrencyCode`, `defaultLanguageCode`, `domainName`, `name`), `participation` (`isParticipating`: "If `true`, the seller participates in the marketplace"; `hasSuspendedListings`: "`true` if the seller Listing Status is set to Inactive") and `storeName`. The default rate is 0.016 requests a second, burst 15.
   - The tutorial names the Selling Partner Insights role; Role Mappings (read 2026-10-14 in `research/method/sp-api-access.md`, A6) gives Product Listing or Selling Partner Insights, either being enough. The door's application holds Product Listing.
   - The existing positions already say what cx does with this reply (P-sp-api-access-1, P-sp-api-access-14; P-marketplaces-and-languages-2).

   [official] (sellers.json at the pin, `models/sellers-api-model/sellers.json`, definitions `MarketplaceParticipation`, `Participation`, `Marketplace`; Get the market participation of a seller, https://developer-docs.amazon/sp-api/docs/get-seller-market-participation.md, updatedAt 2026-09-09, read 2026-10-27)

2. **RULE: one store per definition and per content write.** `getDefinitionsProductType`'s `marketplaceIds` "is limited to one marketplaceId at this time." The FAQ: "the data for each ASIN differs by Amazon store because countries have different data requirements specific to that Amazon store", and "Use the `marketplaceIds` filter in the Product Type Definitions API v2020-09-01 operations to get the Amazon store-specific requirements". The FAQ also answers "No" to a multi-store `JSON_LISTINGS_FEED`: the feed "and Listings Items API v2021-08-01 supports a single Amazon store per feed."
   - `research/method/listing-writes.md` (P-listing-writes-22) already holds one store per content write, with the multi-store exception for `purchasable_offer` patches and deletes.

   [official] (definitionsProductTypes_2020-09-01.json at the pin; Listings APIs FAQ, https://developer-docs.amazon/sp-api/docs/listings-apis-faq.md, updatedAt 2026-09-09, read 2026-10-27)

### B. New item or existing item

3. **RULE: Amazon's two create workflows, and how they are told apart.** The workflows guide has two sections, "List an item that does not already exist in the Amazon catalog" and "List an offer for an item that already exists in the Amazon catalog". Both start the same way:
   - "Call the `searchCatalogItems` operation to search for existing items in the Amazon catalog by product identifiers (for example, UPC, EAN) or keywords. If an exact match is found, follow the steps in List an offer for an item that already exists … If an exact match is not found, continue to the next step."
   - On several matches: "If multiple matches are found, inspect the returned items' attributes (product type, brand, title, parentage level) to identify the correct ASIN. Call the `getCatalogItem` operation for each ASIN to retrieve detailed attributes and validate which product matches your intended item before creating an offer."
   - The FAQ says the same of an offer: "Before creating an offer for an ASIN, use the Catalog Items API to verify if the ASIN exists in Amazon's catalog for the specified Amazon store. If an exact match is found and a valid ASIN is returned, use the Listings Restrictions API to check if you are eligible to list that ASIN. Complete both steps before creating an offer-only listing."
   - `searchCatalogItems` takes `identifiers` with `identifiersType` (`ASIN`, `EAN`, `GTIN`, `ISBN`, `JAN`, `MINSAN`, `SKU`, `UPC`), or `keywords`, never both; `marketplaceIds` is required; `includedData` can name `attributes`, `classifications`, `dimensions`, `identifiers`, `images`, `productTypes`, `relationships`, `salesRanks`, `summaries` and `vendorDetails`. Its default rate is 2, burst 2.

   [official] (Building Listings Management Workflows Guide, https://developer-docs.amazon/sp-api/docs/building-listings-management-workflows-guide.md, updatedAt 2026-09-24, read 2026-10-27; Listings APIs FAQ, as above; catalogItems_2022-04-01.json at the pin, `GET /catalog/2022-04-01/items`)

4. **RULE: the offer-only path.** For an item Amazon has:
   - "Call the `getListingsRestrictions` operation with the ASIN identifier to retrieve any eligibility requirements that must be met before listing an item in the applicable condition."
   - "Call the `getDefinitionsProductType` operation … using the `PRODUCT` product type and `LISTING_OFFER_ONLY` as the value for the `requirements` parameter."
   - "Amazon product types are hierarchal, with the `PRODUCT` product type as the root for all product types. Sales terms are defined on the root `PRODUCT` product type, which should be used when listing items with sales terms only."
   - "Prepare the listing submission with attributes adhering to the JSON Schema for the `PRODUCT` product type using the ASIN or product identifier for the item found when searching the Amazon catalog."
   - "Note that offer-only listings are not supported for vendors at this time."
   - The model's `requirements` enum describes `LISTING_OFFER_ONLY` as "Indicates the submitted data contains sales terms only."
   - Amazon's example body for an offer-only put names the ASIN in `merchant_suggested_asin`, with `condition_type` and the offer attributes (`fulfillment_availability` or `purchasable_offer`).

   [official] (Building Listings Management Workflows Guide, as above; listingsItems_2021-08-01.json at the pin, `ListingsItemPutRequest`; Submit Listings data, https://developer-docs.amazon/sp-api/docs/submit-listings-data.md, updatedAt 2026-10-23, read 2026-10-27)

5. **RULE: the new-item path.** For an item Amazon does not have, the guide's steps after the catalog search are: `searchDefinitionsProductTypes` for the product type; `getDefinitionsProductType` for its schema; prepare the attributes; "Check that the listing data meets requirements prior to submission by using JSON Schema validation utilities … You must ensure that the required attributes are provided, all values are valid, any conditional rules are accounted for, and all schema requirements are met"; `putListingsItem`; read `ACCEPTED` or `INVALID`; then the notifications or `getListingsItem` with `includedData=issues`.
   - On `requirements`: "To list an item with both product facts and sales terms, use the `LISTING` as the value for the `requirements` parameter to retrieve a JSON Schema with both product and offer attributes. To list an item with product facts only, use the `LISTING_PRODUCT_ONLY` … This enables you to create items that are purchasable or procurable in one submission or to create inactive items with sales terms provided later."

   [official] (Building Listings Management Workflows Guide, as above)

6. **RULE: product types not yet in the API.** "For product types not yet launched for these APIs, you can create new offer-only listings items, edit sales terms for listings items, or delete listings items. However, you cannot create new listings items with product facts until the appropriate product type is launched in these APIs." The Listings Items API page adds that for such product types "offer-only submissions for existing ASINs and partial updates are supported by using the `PRODUCT` product type" (as read in `research/method/listing-writes.md`, item 11).
   [official] (Building Listings Management Workflows Guide, as above)

7. **RULE: a put on an existing SKU replaces it.** "The `putListingsItem` operation creates a new listing or replaces the existing content of a listing. Existing attributes may be dropped if omitted from the `putListingsItem` submission. For example, if the listing previously contained bullet points and a `putListingsItem` submission is made with the `LISTING_OFFER_ONLY` requirements without including the bullet points, the `putListingsItem` submission will remove the bullet points content on existing listings."
   - The troubleshooting page, under `4005013`: "The information provided matches an item that is already in your catalog (SKU: `matched_sku`; ASIN: `matched_asin`). Items cannot be duplicated in your catalog." Its explanation: "A SKU is an un-editable attribute; after the item is created, it cannot be changed." Its advice: "Build a workflow to surface any pre-existing catalog data for the SKU using the `getListingsItem` and `getCatalogItem` APIs."

   [official] (Create or fully update a listing, https://developer-docs.amazon/sp-api/docs/create-a-listing.md, updatedAt 2026-09-09, read 2026-10-27; Listings Items API Issues Troubleshooting, https://developer-docs.amazon/sp-api/docs/listings-items-api-issues-troubleshooting.md, updatedAt 2026-09-09, read 2026-10-27)

8. **RULE: restrictions are read by ASIN.** `getListingsRestrictions` requires `asin`, `sellerId` and `marketplaceIds`; `conditionType`, `reasonLocale` and `productType` are optional. Its reason codes are `APPROVAL_REQUIRED` ("A path forward link will be provided"), `ASIN_NOT_FOUND` ("The specified ASIN does not exist in the requested marketplace") and `NOT_ELIGIBLE` ("No path forward link will be provided"). The tutorial: "If there are no restrictions for the specified `conditionType` (when provided) in the specified Amazon store, the list of restrictions in the response will be empty", and "Each Amazon store ID included in the `marketplaceIds` parameter counts as a separate request against the rate limit." The API page: "If no restrictions exist, you can then call the Listings Items API to create offer-only listings."
   - The model describes `productType` as: "The product type of the item. When provided with the brand name, the API evaluates GTIN exemption restrictions in addition to brand restrictions for the specified product type." The operation has no brand parameter at the pin or on `main` (both read 2026-10-27). How the brand name is provided is not stated (open question 2).
   - For a product with no ASIN, no restrictions read exists before creation; `research/method/listing-writes.md` and `research/elements/attributes-and-browse-nodes.md` record that gating on a listing shows as `QUALIFICATION_REQUIRED` issues (P-attributes-and-browse-nodes-23). The model's issue categories include "`QUALIFICATION_REQUIRED`: Approval or qualification is required to list the product."

   [official] (listingsRestrictions_2021-08-01.json at the pin; Listings Restrictions API, https://developer-docs.amazon/sp-api/docs/listings-restrictions-api.md, updatedAt 2026-09-29; Get listings restrictions for an item in the catalog, https://developer-docs.amazon/sp-api/docs/get-listings-restrictions.md, updatedAt 2026-09-30; listingsItems_2021-08-01.json at the pin, `Issue.categories`; all read 2026-10-27)

### C. The product type and its schema

9. **RULE: finding the product type.** `searchDefinitionsProductTypes` takes `keywords` ("**Note:** Cannot be used with `itemName`"), `itemName` ("Title of ASIN to get product type recommendation"), `marketplaceIds` (required), `locale` ("Locale for display names in response") and `searchLocale` ("Language used for `keywords` or `itemName` parameters. Defaults to primary locale of the marketplace"). Each returned product type has `name`, `displayName` and `marketplaceIds`. Its default rate is 5, burst 10.
   - The FAQ: "If you have a product title, you can get a high-confidence recommendation for the product type by passing the `itemName` parameter. With the `itemName` parameter, you can combine the product title and description to get more granular product type suggestions. You can also use `keywords` to search through product types or pass an empty parameter to return the entire list of available product types."
   - The guide: "You don't need to call `searchDefinitionsProductTypes` operation for every new seller or vendor item. Instead, cache the response … and suscribe to `PRODUCT_TYPE_DEFINITIONS_CHANGE`". (Amazon's spelling.)
   - The guide's recommendation wording is "a high-confidence recommendation for the correct product title by passing `itemName`"; the FAQ's is "for the product type". The FAQ's reading is the one the operation's model supports ("Title of ASIN to get product type recommendation").

   [official] (definitionsProductTypes_2020-09-01.json at the pin, `searchDefinitionsProductTypes`; Listings APIs FAQ, as above; Building Listings Management Workflows Guide, as above)

10. **RULE: the schema's parameters for a creation.** `getDefinitionsProductType` takes `productType`; `marketplaceIds` (one); `requirements` (`LISTING`, `LISTING_PRODUCT_ONLY`, `LISTING_OFFER_ONLY`); `requirementsEnforced` (`ENFORCED` default, `NOT_ENFORCED` for partial payloads); `locale` ("Locale for retrieving display labels and other presentation details. Defaults to the default language of the first marketplace in the request"); `productTypeVersion` (`LATEST` default); `parentageLevel` (`NONE`, `CHILD`, `PARENT`); and `sellerId` ("When provided, seller-specific requirements and values are populated within the product type definition schema, such as brand names associated with the selling partner"). Its default rate is 5, burst 10.
    - `parentageLevel`: "When provided, the schema is simplified by resolving all conditional logic related to the specified parentage level". The Retrieve page's table: `CHILD` "The `parent_sku` attribute is required"; `PARENT` "Includes attributes applicable to variation group containers"; `NONE` "Variation-related attributes are excluded." "When `parentageLevel` is omitted, the full schema with all conditional logic is returned."
    - The Retrieve page on `sellerId`: "Include the optional `sellerId` parameter to retrieve the seller-specific attributes, including B2B audience values … If the `sellerId` is not provided, the API returns a generic schema without the seller-specific configurations."
    - The schema itself is a link: "The links provided are valid for seven days." The response carries `productTypeVersion` (`version`, `latest`, `releaseCandidate`), `propertyGroups`, and a `checksum` on `schema` and `metaSchema` (`research/method/listing-writes.md`, items 3–5, P-listing-writes-1, P-listing-writes-15).

    [official] (definitionsProductTypes_2020-09-01.json at the pin, `getDefinitionsProductType`; Retrieve a Product Type Definition, https://developer-docs.amazon/sp-api/docs/retrieve-a-product-type-definition.md, updatedAt 2026-09-09, read 2026-10-27)

11. **RULE: which schema keywords decide what a value must look like.** The meta-schema extends JSON Schema Draft 2019-09 with a custom vocabulary: "If you choose to ignore this custom vocabulary and use only the standard JSON Schema Draft 2019-09 vocabularies, you may get validation errors." Its keywords:
    - `editable`: "Indicates whether or not a property value can be modified for an existing item. Properties that can't be modified may still be required for a valid submission."
    - `enumNames`: "Contains an array of display labels for a corresponding array of `enum` values." The value written is the `enum` value, not its label (as `research/method/listing-writes.md` and P-inventory-and-fulfillment-15 already hold for shipping templates).
    - `maxUtf8ByteLength` / `minUtf8ByteLength`: "measured in UTF-8 bytes".
    - `selectors`: "Contains an array of property names that define the combination of properties that make an object unique."
    - `maxUniqueItems` / `minUniqueItems`: "Defines the maximum number of unique items in an array. Use in conjunction with `selectors`."
    - `$lifecycle`, `replacedBy`, `replaces`, `enumDeprecated` ("Instances of deprecated `enum` values must be replaced with valid values before the deprecated values are removed").
    - `hidden`: "Determines if a property should be hidden in Amazon user interfaces." It is "Informational".
    - Beyond the vocabulary, the standard keywords the guide names are what make a submission valid: "the required attributes are provided, all values are valid, any conditional rules are accounted for". The guide's variation section names the conditional form: "When `parentageLevel` is not provided, refer to the conditional requirements (`allOf`) within the `ProductTypeDefinition` to identify which properties become mandatory based on the selected variation theme."

    [official] (Amazon Product Type Definitions Meta-Schema (v1), https://developer-docs.amazon/sp-api/docs/product-type-definition-meta-schema.md, updatedAt 2026-09-09, read 2026-10-27; Building Listings Management Workflows Guide, as above)

12. **RULE: the schema's property groups.** Amazon's LUGGAGE example response groups its properties as `offer`, `images`, `shipping`, `variations`, `safety_and_compliance`, `product_identity` and `product_details`. `product_identity` is described as "Information to uniquely identify your product (e.g., UPC, EAN, GTIN, Product Type, Brand)" and lists `item_name`, `brand`, `supplier_declared_has_product_identifier_exemption`, `externally_assigned_product_identifier`, `merchant_suggested_asin`, `item_type_keyword`, `item_type_name`, `model_number` and `manufacturer`. `safety_and_compliance` is "Information to indicate product compliance, hazardous materials, and legal and safety warnings (e.g., lithium batteries, choking hazards, Consumer Product Safety Information Act (CPSIA))". The group lists are one product type's in one store; the run-time schema holds the set for the seller's product type and store.
    [official] (Manage Product Listings with the Selling Partner API, https://developer-docs.amazon/sp-api/docs/manage-product-listings-guide.md, updatedAt 2026-09-09, read 2026-10-27)

13. **RULE: the schema changes.** The FAQ: "Amazon reviews product attributes regularly and plans necessary updates for the last week of every month … Before you update any attribute for your listing submission, use the Product Type Definitions API to get the latest JSON schema." A schema change shows in `checksum`, in `PRODUCT_TYPE_DEFINITIONS_CHANGE`, and in the monthly announcements. (`research/method/listing-writes.md`, item 5; P-listing-writes-15.)
    [official] (Listings APIs FAQ, as above)

### D. Product identity

14. **RULE: the identifier attribute and its lengths.** The troubleshooting page lists, under `90225`, "`externally_assigned_product_identifier`: 12 characters expected for UPC, 13 for EANs, 14 for GTINs". Under `90188`, "Value does not satisfy ISBN/UCCID. Checksum requirements": "Each `external_id_type` has an expected number of characters … 12 characters expected for UPC, 13 characters expected for EANs, 14 characters expected for GTINs." The attribute's inner properties (its type and value fields) are the schema's, read at run time.
    [official] (Listings Items API Issues Troubleshooting, as above)

15. **RULE: whose GTIN.** Product detail page rules: "You must only use GTINs that you own or are authorized to use. GTINs must be purchased directly from GS1, or you must have explicit authorization from the GTIN prefix owner. Listing submissions with unauthorized GTINs will be blocked." "You must not use false product identification information in product detail pages." "You must not create a product detail page for a product already in Amazon's catalog." "Unless your listing was created with a GTIN exemption, you cannot edit or update the product ID of an existing listing. The product ID is a non-editable value and cannot be modified once a listing is created, unless it was created with a GTIN exemption."
    - The troubleshooting page's identity issues:
      - `4005007`: "A match for the value of `attribute_name` could not be found for the brand specified." Explanation: "This issue is returned when the item submitted has an external ID that is not registered for use with the provided brand … If correct, you need to provide proof of affiliation between the company the External ID is registered to and the brand you selected (for example, a license agreement)." The listed evidence ends "GS1 Certificate for the UPC/EANs should be attached in the related Item."
      - `4005008`: "The value of `attribute_name` is either restricted or not registered in GS1. Contact Amazon to provide the relevant GS1 certificate."
      - `100980`: "Your barcode is already associated with another product ASIN, which appears to be different from the product you are trying to list." Advice: "Use the Catalog Items API to look up existing ASINs associated with the barcode."
      - `101165`: "Your item with `SKU`, external product ID, and ASIN matches multiple products because these identifiers are not unique."
      - `101166`: "Amazon requires a one-to-one mapping between SKUs and external product IDs. Each unique ASIN and external ID combination must have its own distinct SKU."
      - Several of these rows send the reader to Vendor Central or a vendor manager; the page does not give the seller route for each.

### E. The request

18. **RULE: the put request.** `PUT /listings/2021-08-01/items/{sellerId}/{sku}`. Path: `sellerId` ("A selling partner identifier, such as a merchant account or vendor code") and `sku` ("A selling partner-provided identifier for an Amazon listing"). Query: `marketplaceIds` (required), `includedData` (`identifiers`, `issues`; "Default: `issues`"), `mode` (`VALIDATION_PREVIEW`), `issueLocale`. Body: `productType` and `attributes` (required) and `requirements` (`LISTING`, `LISTING_PRODUCT_ONLY`, `LISTING_OFFER_ONLY`). The model's default rate is 5, burst 10; the rate-limit page gives 5 per account-application pair, 100 per application, burst 5, with relationship updates at 100 a second per application.
    - Amazon's create example: `PUT …/listings/2021-08-01/items/AXXXXXXXXXXXXX/ABC123?marketplaceIds=ATVPDKIKX0DER&issueLocale=en_US` with `{"productType": "LUGGAGE", "requirements": "LISTING", "attributes": {"condition_type": […], "merchant_suggested_asin": […], "item_name": [{"value": …, "language_tag": "en_US", "marketplace_id": …}], "brand": […], "color": […], "main_product_image_locator": [{"media_location": …, "marketplace_id": …}], …}}`.
    - That example names `merchant_suggested_asin` on a full `LISTING` put. The guide's new-item path names no ASIN, and the FAQ's GTIN answer names a product identifier or the exemption. The example is read as a listing against a known ASIN, not as the new-item shape (the same reading `research/method/listing-writes.md`, item 13, gives a mislabelled example: the model and the workflow decide).
    - The seller id in the path is read from an Amazon reply, never asked (P-sp-api-access-3; the door's `references/door.md`).

    [official] (listingsItems_2021-08-01.json at the pin, `putListingsItem`, `ListingsItemPutRequest`; Submit Listings data, as above; Listings Items API Rate Limits, https://developer-docs.amazon/sp-api/docs/listings-items-api-rate-limits.md, updatedAt 2026-09-09, read 2026-10-27)

19. **RULE: text values carry the store's language.** Amazon's examples write text with `language_tag` and `marketplace_id` (`research/method/listing-writes.md`, item 7; P-listing-writes-4, P-marketplaces-and-languages-7). ### F. Variations

24. **RULE: parent first, then children.** "With the Listings Items API and `JSON_LISTINGS_FEED`, a parent listings item is created first and each child listings item refers to the parent listings item with the child_parent_sku_relationship attribute." The guide:
    - Parent: schema with `parentageLevel=PARENT`; "A parent listings item must have the following attributes: `parentage_level`: `value` property set to `parent`; `child_parent_sku_relationship`: `child_relationship_type` property set to `variation`; `variation_theme`: `name` property set to a value applicable for your product". "The parent listing is a non-buyable entity used to relate child products. A parent listing must not be a buyable product."
    - Children: schema with `parentageLevel=CHILD`; "Most product facts must be replicated across all listings within the variation family." Each child has `parentage_level` `child`, `child_parent_sku_relationship` with `child_relationship_type` `variation` and `parent_sku` "set to the SKU identifier of the parent listings item", and `variation_theme` "set to the same value as the parent listing item".
    - "When you select a variation theme for a child listing item, you must provide the corresponding properties. … When using `parentageLevel=CHILD`, these mandatory properties appear directly in the schema as required attributes."
    - "new listings must avoid using deprecated enumeration values" (`enumDeprecated` in `$lifecycle` within `variation_theme`).
    - Standalone listings: "include `parentageLevel=NONE` … Variation-related attributes are excluded from the returned schema."
    - Reading the family back: `getCatalogItem` or `searchCatalogItems` with `includedData=relationships`, or `searchListingsItems` with `variationParentSku`.
    - Relationship writes have their own rate: "Ensure updates containing relationship updating attributes (`child_parent_sku_relationship`, `package_contains_sku`) do not exceed the application's rate limit for relationship updates."
    - The family rules (non-varying attributes, same function, review sharing) are in `research/elements/variations.md` (P-variations-2, P-variations-4, P-variations-14).

### H. The write and what it answers

28. **RULE: `ACCEPTED` and `INVALID` on a creation.** "Inspect the response to identify if the submission status was `ACCEPTED` or `INVALID`. If accepted, initial validations have passed and the data has been submitted for further processing with the Amazon catalog.     [official] (Building Listings Management Workflows Guide, as above; listingsItems_2021-08-01.json at the pin, `ListingsItemSubmissionResponse`)

29. **RULE: asynchronous issues and the read-back.** The FAQ: "If you upload the listings data with the Listings Items API v2021-08-01 and the submission status is `ACCEPTED`, then the submission passed the synchronous validations. Amazon sends the submission downstream to create or update the SKU. There are a number of downstream processes that are then performed to create or update an item in the Amazon catalog. Any of these downstream processes can generate issues which are returned asynchronously. For example, if a listing submission contains data which conflicts with another item in the Amazon catalog."
    - "I submitted my listing without issues, but I cannot find it listed. Where is it?" "Your listing might have experienced an issue after submission (an asynchronous issue). To view such issues, use the `getListingsItem` operation."
    - "Why is there no summary information in my Listings Item Get API response?" "The summary view displays information about the ASIN you are creating a listing against. If the summary view is not populated it is because the submission failed and did not match an ASIN."
    - "How can I confirm the creation of my product in the Amazon catalog?" Amazon sends `LISTINGS_ITEM_STATUS_CHANGE` "when the buyability changes for a listing item, or upon the creation or deletion of a listing item … For example, if `DISCOVERABLE` is not present, Amazon retail cannot search for the listings item."
    - The status enum: `BUYABLE`, "The listings item can be purchased by shoppers. This status does not apply to vendor listings"; `DISCOVERABLE`, "The listings item is visible to shoppers." A summary carries `marketplaceId`, `asin`, `productType`, `status`, `createdDate` and `lastUpdatedDate`.
    - `getListingsItem` takes `includedData` of `summaries`, `attributes`, `issues`, `offers`, `fulfillmentAvailability`, `procurement`, `relationships` and `productTypes`.
    - The FAQ's timing: `getListingsItem` "directly queries the current state, which is why the results are available faster (within 1-5 minutes)"; the notifications run 15–20 minutes behind. The door subscribes to no notifications (P-triggers-12, as recorded in `research/README.md`, T6), so every read-back is a pull.
    - The September 30, 2026 release notes: "Added PRODUCT-level and LISTING-level issue classification to the `categories` attribute in issue descriptions returned by the `getListingsItem` and `searchListingsItems`. You can use this to identify whether an issue originates from the ASIN (product level) or the SKU (listing level)."
    - No page read states how long Amazon takes to assign an ASIN to a new item.

## Stable enough for a skill

- **The order.** The stores; the catalog search by identifier; the offer-only path for an exact match, the new-item path otherwise; the product type; the store's schema; the request; the preview; the write; the read-back. This order is Amazon's own (items 3–5) and does not depend on any figure.
- **New against existing.** An exact `searchCatalogItems` match by identifier means an offer-only listing on that ASIN; no match means a new item with product facts (item 3).
- **Per store.** One schema and one put per store, each in its language and currency (items 2, 19, 20).
- **The schema decides the value.** `required` and its conditionals, `enum` (not `enumNames`), `enumDeprecated`, the length keywords, `selectors`, `maxUniqueItems` and the seller-specific enums decide what a value must look like (items 10, 11, 21).
- **Identity.** A GTIN the seller owns or is licensed to use, or an approved exemption with the brand exactly as approved (items 15, 16). The product ID cannot be changed after creation except under an exemption (item 15).
- **The preview.** Persists nothing; answers `VALID` or `INVALID` with issues naming attributes (items 25, 26).
- **The write.** `ACCEPTED` means the synchronous checks passed and processing began; asynchronous issues follow on `getListingsItem` (items 28, 29).
- **Done.** `summaries` with an ASIN, `status` holding `BUYABLE` and `DISCOVERABLE`, and no `ERROR` issue, read back, never assumed after a wait (item 29).
- **Variations.** Parent first, then children, each with the relationship and the parent's theme (item 24).
- **Sandbox.** Shape and route only (item 31).

## What cx must read at run time

- **The stores:** `GET /sellers/v1/marketplaceParticipations` on each connected origin; `marketplace.id`, `defaultLanguageCode`, `defaultCurrencyCode`, `participation.isParticipating`, `participation.hasSuspendedListings`.
- **The seller id:** from the reply the door names (`references/door.md`; P-sp-api-access-3).
- **Whether the SKU exists:** `GET /listings/2021-08-01/items/{sellerId}/{sku}` for that store, before a put replaces it (item 7).
- **Whether Amazon has the item:** `GET /catalog/2022-04-01/items` with `identifiers`, `identifiersType` and `marketplaceIds`, and `includedData=summaries,attributes,identifiers,productTypes,relationships`; `getCatalogItem` per candidate ASIN where several match.
- **For an existing ASIN:** `GET /listings/2021-08-01/restrictions` with `asin`, `sellerId`, `marketplaceIds` and `conditionType`.
- **The product type:** `GET /definitions/2020-09-01/productTypes` with `itemName` (or `keywords`), `marketplaceIds` and `searchLocale`.
- **The schema, per store:** `GET /definitions/2020-09-01/productTypes/{productType}` with one `marketplaceIds`, `requirements`, `sellerId`, `locale` and `parentageLevel`; then the schema document at `schema.link.resource`; keep `productTypeVersion.version` and `schema.checksum`.
- **The preview:** `PUT /listings/2021-08-01/items/{sellerId}/{sku}?marketplaceIds=…&includedData=identifiers,issues&mode=VALIDATION_PREVIEW&issueLocale=…`.
- **The write:** the same request without `mode`.
- **The read-back:** `GET /listings/2021-08-01/items/{sellerId}/{sku}` with `includedData=summaries,attributes,issues,offers,fulfillmentAvailability,relationships`; then `getCatalogItem` on the ASIN the summary names.
- **Rates:** `x-amzn-RateLimit-Limit` on each reply (P-sp-api-access-11).

## Open questions

1. **ASIN assignment time.** No page read says how long a new item takes to get an ASIN or to become `BUYABLE` and `DISCOVERABLE`. *Settles:* the first real creation, read back on a cadence and timed.
2. **Restrictions by brand.** The restrictions model says `productType` "When provided with the brand name" evaluates GTIN-exemption restrictions, but the operation has no brand parameter. *Settles:* Amazon's reference page or a developer support answer.
3. **What a new item's product identifier looks like in the schema.** The inner properties of `externally_assigned_product_identifier` (the type field and its `enum`) and whether a store's schema still carries an older identifier attribute. *Settles:* the first `getDefinitionsProductType` for the seller's product type and store.
4. **The preview's `identifiers` for a new item.** Whether a preview of a new item with no catalog match returns an empty `identifiers`, a would-be match, or an issue. *Settles:* the first real preview.
5. **Does a preview run the identity checks?** Whether `4005007`, `4005008`, `100980` and the like come back on a preview, or only asynchronously after a write. The FAQ says the preview runs "the same checks that are done on production submissions" synchronously; the catalog-matching issues the AI sandbox drops (`research/method/listing-writes.md`, item 19) suggest some are judged against the live catalog. *Settles:* the first real preview with the seller's GTIN.
6. **Seller Central brand codes through the API.** Whether 5461 and 5665 reach a Listings Items `issues` read under those codes. *Settles:* a real write that meets one.
7. **The GTIN exemption page.** G200426310 was not read. *Settles:* the office's ruling on the content call, or a signed-in read by the seller or Jack.
8. **WEEE and EPR in a listing.** Whether any EU store's schema names a WEEE or packaging-EPR attribute. *Settles:* `getDefinitionsProductType` for the seller's product type in each EU store named.
9. **Children in the same request window as the parent.** Whether a child put sent before the parent's creation finishes processing is refused or held. The pages say only that the parent is created first. *Settles:* the first family creation, read back between the parent and the children.

## Positions

- **P-listing-create-1.** The marketplaces a creation goes to are those the seller names, each checked against `getMarketplaceParticipations` (`isParticipating`, `hasSuspendedListings`), and each store's `defaultLanguageCode` and `defaultCurrencyCode` come from its row. Sources: sellers.json; Get the market participation of a seller.
- **P-listing-create-2.** Before a creation in a store, cx searches that store's catalog with `searchCatalogItems` by the product's identifier and `identifiersType`: an exact match is an existing item and gets an offer-only listing on that ASIN, after `getListingsRestrictions`; no match is a new item with product facts; several matches are told apart by product type, brand, title and parentage level through `getCatalogItem`. Sources: Building Listings Management Workflows Guide; Listings APIs FAQ; catalogItems_2022-04-01.json.
- **P-listing-create-3.** An offer-only listing is a put with `productType` `PRODUCT` and `requirements` `LISTING_OFFER_ONLY`, against the schema read with those values, naming the ASIN the catalog search found, and a vendor cannot list offer-only. Sources: Building Listings Management Workflows Guide; Submit Listings data; listingsItems_2021-08-01.json.
- **P-listing-create-4.** A new item's product type is found with `searchDefinitionsProductTypes` by `itemName` (the title, which may be combined with the description) or by `keywords`, never both, in the store's `searchLocale`, and a product type the API has not launched admits no new item with product facts, only offer-only listings. Sources: definitionsProductTypes_2020-09-01.json; Listings APIs FAQ; Building Listings Management Workflows Guide.
- **P-listing-create-5.** The schema for a creation is read for each store named, with one `marketplaceIds`, `requirements` `LISTING` (or `LISTING_PRODUCT_ONLY` for an item without sales terms yet), the seller's `sellerId`, and `parentageLevel` `NONE`, `PARENT` or `CHILD` for the listing being made, and its document is fetched from `schema.link.resource` within its seven days. Sources: definitionsProductTypes_2020-09-01.json; Retrieve a Product Type Definition; Building Listings Management Workflows Guide; Listings APIs FAQ.
- **P-listing-create-6.** What a value must look like is decided by the schema: `required` and its conditional `allOf`, the `enum` value (not its `enumNames` label), `enumDeprecated`, `maxLength` and `maxUtf8ByteLength`, `selectors`, `maxUniqueItems`, `editable`, and the seller-specific enums the `sellerId` read fills (brand names, fulfilment channel codes, shipping templates); the meta-schema's custom vocabulary is part of validation, so reading the schema as plain JSON Schema misses rules Amazon checks. Sources: Amazon Product Type Definitions Meta-Schema (v1); Building Listings Management Workflows Guide; definitionsProductTypes_2020-09-01.json; Manage Amazon Haul, Advanced Multiple-Offer, and Multiple-Fulfillment Use Cases; Submit Listings data.
- **P-listing-create-7.** A creation is `PUT /listings/2021-08-01/items/{sellerId}/{sku}` with one `marketplaceIds`, `includedData=identifiers,issues` and `issueLocale`, and a body of `productType`, `requirements` and `attributes` built from the seller's data in the schema's names and shapes, one store per request. Sources: listingsItems_2021-08-01.json; Submit Listings data; Listings APIs FAQ.
- **P-listing-create-8.** A put on a SKU that already exists replaces its content and drops what it omits, and a SKU cannot be changed after creation, so cx reads `getListingsItem` on the SKU before a creation and does not reuse a SKU the seller already lists. Sources: Create or fully update a listing; Listings Items API Issues Troubleshooting (4005013).
- **P-listing-create-9.** A new item's identity is a GTIN, UPC or EAN the seller owns from GS1 or is licensed by the prefix owner to use, in `externally_assigned_product_identifier` at the length its type takes, with the brand it is registered to, and the product ID cannot be edited after creation unless the item was created under a GTIN exemption. Sources: Product detail page rules (G200390640 v21); Listings Items API Issues Troubleshooting (90225, 90188, 4005007, 4005008, 100980).
- **P-listing-create-10.** A product without a GTIN is created only after the seller's GTIN exemption is approved in Seller Central, with `supplier_declared_has_product_identifier_exemption` set to `true` and the brand (and category) exactly as the approval names them. Sources: Listings APIs FAQ; Seller Forums "Listing Lounge: Your GTIN Exemption Was Approved…".
- **P-listing-create-11.** For a brand enrolled in Brand Registry, creating a detail page takes the brand's own account or one the brand authorised, and a refusal on brand grounds is answered through the brand's approval route, not by changing the brand to generic. Sources: How to create Amazon product listings (sell.amazon.com); Product detail page rules (G200390640 v21); Seller Forums "Listing Lounge…".
- **P-listing-create-12.** Text values are written in the store's language with the `language_tag` the store's schema allows, the schema's `locale` sets only display labels, and the price is a `purchasable_offer` in the store's currency with its `currency`, `audience` and `marketplace_id` selectors. Sources: definitionsProductTypes_2020-09-01.json; sellers.json; Manage purchasable offer; Submit Listings data.
- **P-listing-create-13.** A merchant-fulfilled offer is a `fulfillment_availability` record with `fulfillment_channel_code` `DEFAULT` and a `quantity` (and the handling time the schema offers), while an FBA offer names the seller's Amazon channel code without a quantity and needs the dangerous-goods and battery information Amazon requires for FBA, and the codes come from the seller-specific schema. Sources: Manage Amazon Haul, Advanced Multiple-Offer, and Multiple-Fulfillment Use Cases; Submit Listings data; Dangerous goods identification guide (as cited in attributes-and-browse-nodes.md).
- **P-listing-create-14.** Images are given as locations Amazon fetches (public HTTPS on S3, CloudFront or a third-party server, or a private S3 bucket Amazon's role may read), in the image attributes the store's schema offers, and new content takes a new location. Sources: Submit media attributes; Building Listings Management Workflows Guide.
- **P-listing-create-15.** The compliance attributes a store's schema names, GPSR in an EU store among them, are filled from the seller's own declarations at creation, store by store, and a required one the data lacks is asked of the seller, never inferred. Sources: Update: Support for GPSR compliance in Listings Items API (as cited in marketplaces-and-languages.md); Submitting manufacturer, Responsible Person, and warning and safety information (as cited there); Dangerous goods identification guide (as cited in attributes-and-browse-nodes.md); How to create Amazon product listings (sell.amazon.com).
- **P-listing-create-16.** A variation family is written parent first (`parentage_level` `parent`, `child_parent_sku_relationship` with `child_relationship_type` `variation`, a `variation_theme` the schema offers and not deprecated, no offer) and then each child (`parentage_level` `child`, the relationship with the parent's SKU in `parent_sku`, the parent's theme and the theme's attributes), each child repeating the family's product facts. Sources: Building Listings Management Workflows Guide; Submit Listings data; Retrieve a Product Type Definition.
- **P-listing-create-17.** A preview of a creation is the same put with `mode=VALIDATION_PREVIEW`, which runs production's synchronous checks without persisting anything and answers `VALID` or `INVALID` with its issues, and a required attribute the data does not fill comes back `INVALID` with an issue (such as `90220`, category `MISSING_ATTRIBUTE`) naming it in `attributeNames`. Sources: Preview errors before creating or fully updating a listing; Listings APIs FAQ; Listings Items API Issues Troubleshooting (90220); listingsItems_2021-08-01.json.
- **P-listing-create-18.** A write's `ACCEPTED` means the synchronous checks passed and the submission went downstream, `INVALID` means it was not accepted, and the `submissionId` identifies it; issues from the downstream processing, such as a conflict with another catalog item, appear only on a later `getListingsItem`. Sources: Building Listings Management Workflows Guide; Listings APIs FAQ; listingsItems_2021-08-01.json.
- **P-listing-create-19.** A creation is done when `getListingsItem` for that store shows a summary with an ASIN, `status` holding `BUYABLE` and `DISCOVERABLE`, and no `ERROR` issue; an empty summary means no ASIN was matched or made yet, and since no page states how long that takes, cx reads back rather than waits a figure. Sources: Listings APIs FAQ; listingsItems_2021-08-01.json; Manage Product Listings with the Selling Partner API.
- **P-listing-create-20.** The static sandbox answers a creation by pattern (an empty body `ACCEPTED`, fixed `VALIDATION_VALID` and `VALIDATION_INVALID` SKUs, one product type, a placeholder schema link), so it proves a request's path, signing and shape, never the product type, the schema, the identity or what Amazon would answer for the seller's product. Sources: Selling Partner API Sandbox; listingsItems_2021-08-01.json; definitionsProductTypes_2020-09-01.json.
- **P-listing-create-21.** Build International Listings is a Seller Central tool that creates offers where the same ASIN exists in both stores and attempts translated pages it does not guarantee, so a creation in each named store goes through that store's own schema, preview and put. Sources: Build International Listings (G202121570 v14); Listings APIs FAQ.
- **P-listing-create-22.** `getListingsRestrictions` is read by ASIN, so it applies to an offer-only listing, and a new item's approval requirement shows as a `QUALIFICATION_REQUIRED` issue on the preview or the write. Sources: listingsRestrictions_2021-08-01.json; Get listings restrictions for an item in the catalog; listingsItems_2021-08-01.json.
- **P-listing-create-23.** Amazon keeps no history of a listing, so a creation is a change whose before is empty, and what cx sent and what Amazon answered are kept only in the change log. Sources: listingsItems_2021-08-01.json; Listings Items API (as cited in listing-writes.md).

### The seat's own (not for a skill)

- [seat] For GL's trial, the most likely blocker is identity rather than content: a GTIN not registered to the brand on the listing, or a brand in Brand Registry whose account is not the one connected. Both show only on a real preview or a real write (open question 5).
- [seat] The preview is the cheap place to learn a store's requirements: a deliberately thin preview lists what the store's product type requires, but the schema already lists it, so the preview's value is in the checks the schema cannot express (pricing, identity, catalog conflicts).
- [seat] A family's children can be previewed before the parent exists, but whether a child's preview judges `parent_sku` against a parent not yet created is not known (open question 9); parent first in both preview and write is the safe order.
- [seat] The sell.amazon.com guide's "up to five bullets" and "up to nine photos" are Seller Central form figures, not the schema's; they are left in *Facts for human readers only* in `research/README.md`.
